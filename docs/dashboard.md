# Dashboard

Реализация заменяет заглушку `/dashboard` в существующем интерфейсе Mineral Light.
Оболочка, шрифты, семантические цвета, навигация, инспектор и форма работы используются
из проекта. Новых зависимостей и изменений схемы БД нет.

## Требования и поведение

- ТЗ, раздел 10: панель уровней риска — сводка, распределение по уровням и системам,
  реестр прогнозов. Карта и уведомления остаются в действующих Network и Notification Center;
  из панели есть переходы на Network и Actions.
- ТЗ, раздел 12: выбранный прогноз открывает инспектор с горизонтом, временем снимка,
  моделью и факторами. Create action открывает существующую форму с причиной и привязкой
  к prediction/model/score/horizon. Сохранение и результат работы — существующий процесс Actions.
- Все блоки и CSV используют одни фильтры: горизонт 24/72ч, система, уровень риска, поиск.
  В таблице 20 строк на страницу; CSV содержит всю отфильтрованную выборку.
- Заголовки Asset / group, System, Risk, Score, Horizon и Response переключают сортировку.
  Повторное нажатие меняет направление; стрелка и aria-sort показывают текущий порядок.
  Сортируется вся выборка до пагинации, после изменения порядка открывается первая страница.
  CSV сохраняет выбранный порядок. Недоступные score остаются в конце при обоих направлениях.
- В API-режиме загружаются все страницы `/predictions?horizon=…`, по 500 записей.
  Смена snapshot_id, дубли, неверный горизонт, некорректный ответ и сбой любой страницы
  отклоняют всю загрузку. При превышении 100 000 записей выводится ошибка, а не усечённый итог.
- Counts различают число объектов и число прогнозов: один объект может иметь несколько моделей.
  Without an action считает уникальные объекты Critical/Attention без открытой работы.
  Suggested тоже считается открытой работой. Закрытая работа не исключает объект из этого числа.
- Нет подмены недоступного API демо-значениями. Ошибка прогнозов скрывает счётчики;
  ошибка работ сохраняет риски, но выводит недоступность сводки работ.
- Риск сохраняет уровень из API. Неоткалиброванный score выводится как N/100,
  calibrated_probability — как процент. Точное время отказа не выдумывается.
- Неизвестные реестру объекты остаются в аналитике. Для них недоступны Timeline и
  создание работ до сопоставления с реестром; причина видна в инспекторе.
- Это реестр текущего снимка, не серверный архив всех предыдущих прогнозов.
  Результаты работ не выдаются за метрики качества модели.

## Воспроизведение

Из `frontend/`, используя указанную в package.json версию pnpm 10.9.0:

```sh
pnpm install --frozen-lockfile
pnpm lint
pnpm test
pnpm build
pnpm typecheck
pnpm start --hostname 127.0.0.1 --port 3101
```

Открыть http://127.0.0.1:3101/dashboard. По умолчанию используются детерминированные
demo fixtures и локальные работы существующего проекта. Для API указать
`NEXT_PUBLIC_VENA_WORKFLOW_MODE=api` и `NEXT_PUBLIC_API_URL` до сборки; нужен рабочий backend.

Проверки включают пагинацию 501 записи, сбой второй страницы, смену снимка,
валидацию типов, горизонты, уникальные объекты, закрытые/открытые работы,
фильтры и защиту CSV от формул. Живой backend этой локальной проверкой не разворачивается.
