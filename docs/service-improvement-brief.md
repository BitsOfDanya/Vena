# План улучшения сервиса Vena (отображение и продуктовый контур)

Документ — рабочий бриф для последующих изменений в коде.  
Источник: замечания по защите / демо, gap-анализ ТЗ, ориентиры APM, задачи «Вадим — отображение и вид».  
Сверка с текущим `main` (после reset на актуальный remote).

**Жёсткое ограничение:** дизайн-систему, тему Mineral Light, визуальный язык, типографику, цветовую палитру и композиционные паттерны **не менять**. Улучшаем содержание, иерархию информации, тексты, фильтры, связку данных и сценарии — в существующих компонентах (`shared/ui`, текущие layout-паттерны экранов).

## 1. Диагноз: почему «скучно / мёртво»

| Симптом | Корневая причина | Что уже есть в коде | Что нужно |
|---|---|---|---|
| Всё «мёртвое», баннер outdated | На стенде по умолчанию `demo` / старый snapshot; stale notice на каждом экране | Stream API, worker, `VENA_ML_MODE=journal`, stale thresholds | Живой replay / свежий поток + умный баннер (демо ≠ ошибка) |
| Очередь однообразна («потеря питания») | Ранжирование по риску выдаёт доминирующий сценарий | Инциденты: flooding / fire / power_loss / ventilation; лимиты на бэке | Фильтры/вкладки сценариев на Pulse; квоты видимости |
| Нет ответа «почему» | Сырые факторы / tech labels вместо человеческого текста | `drivers` в snapshot, `primaryReason` в situations | Шаблон объяснения + рекомендация + похожие исходы |
| Два мира: демо UI ↔ числовые ID | Pulse/Network/Map на fixtures; прогнозы по каналам СМВУ | `GET /assets/tree`, spatial API, prediction overlay | Склеить реестр/дерево с рисками на Network |
| Нет ответа руководителю | Effect/XLSX есть в API, нет экрана | `GET /analytics/effect`, `GET /reports/management.xlsx` | Экран «Эффект» + выгрузка; PDF позже |
| Визуальная монотонность (без смены стиля) | Равная визуальная плотность «Normal» и критичного | Dashboard distribution включает Normal | Убрать Normal с главного фокуса; усилить сценарии, не палитру |

Ориентиры рынка (не копировать UI): Maximo APM / AVEVA / GE / Senseye / «Цифра» / Clover — **Health Index**, горизонт отказа, FMEA→действие, тикеты, корреляция (у нас уже инциденты), экономика, мобильный наряд.

## 2. Что уже закрыто (не переделывать с нуля)

Использовать и дотягивать UI/тексты, а не дублировать backend:

- Калиброванные вероятности, модели flood/fire proxies, alarm, phase — см. README «Модели».
- Инциденты по сценариям + situations API.
- SMVU stream + пересчёт ≤300 с (по доке); journal mode.
- Health index в `backend/app/domain/health.py`, в tree и XLSX — **UI есть** (Dashboard HealthStrip, AssetTree, situations).
- Effect report API + management XLSX — **экран `/effect` есть**; печать/PDF через браузер.
- Dashboard: сводка, seasonality, prospective, CSV, inspectors с drivers.
- Auth: password + JWT, seed users (не LDAP); вход для жюри с подсказками.
- Alarms / Journal / Actions / Timeline / Settings — RU-унификация продуктовых строк.
- Карточка инцидента: Почему (hint/drivers) / Что делать / горизонт «≈ через N дн.» / Создать работу.
- Pulse-фильтры сценариев + diversity на бэке.
- Баннер: демо → «Демонстрационный режим».
- Network: режим «Дерево» по реальному реестру + фильтры risk/system + risk_by_scenario.
- Карточка: history эпизодов, чеклист РТЭК, «В дереве», prefill работы из recommendation.
- Effect: сорт по HI, RU status, print CSS, заголовок-сводка.
- Demo-телеметрия на Pulse свёрнута в api+demo; маршрут защиты на форме входа.
- ⌘K: Эффект, Алармы, Журнал; Dashboard default 24ч + все объекты; HI = минимум + count&lt;40.
- **P0 (защита 2026-09):** страница `/models` (язык диспетчера), карточка ситуации (что/где/когда/почему/последствие/делать/раньше/здоровье/модель + feeder), график прогноз×факт на Эффекте, CSV/XML рядом с XLSX, ISA-18.2 на Алармах/Эффекте, Таймлайн на реальных channel_id.
- **Production harden:** Pulse counts = Dashboard snapshot+horizon; `location_group`/`what`/`model_id` в situations; `/about` «Как работает VENA»; picket-strip маршрутов; honesty-баннеры на Timeline/Network; ForecastVsFact через select.
- **Поле / руководитель (дотяг):** мобильный наряд на `/actions` (принять → начать → закрыть); тренд тревог по месяцам ISA; HI объектов + Δ за 7 дней на Dashboard; RU aria/CSV.
- **Production-ready (2026-09):** overlay с горизонтом+pagination; API assets/inspector через `/assets/{id}/prediction`+drivers; без синтетического forecast на Timeline; Pulse без demo-телеметрии по умолчанию; feeder match по tag/id; KPI Dashboard = полный снимок; rising с horizon.
- **P0 план осмотров:** `GET /analytics/inspection-plan` (pump_72h + fan_72h) на Pulse и Actions · «Создать работу» · fans skip recent.

## 3. Принципы изменений

1. **No redesign** — те же tokens, spacing patterns, Segmented/Inspector/StateMessage/таблицы.
2. **Один язык в UI** — русский в меню, заголовках, кнопках, подписях; EN только для ID моделей/технических имён.
3. **Сценарии ТЗ, не только типы оборудования** — пожар / подтопление / питание / вентиляция (+ доступ / ложные по мере данных).
4. **Честность данных** — не подменять API демо-рисками; демо-телеметрию явно маркировать или убирать со стенда journal.
5. **Сначала диспетчер, потом руководитель** — P0 = «что горит сейчас и почему»; P1 = эффект и Health Index.
6. **Переиспользовать API** — tree, effect, event-types, drivers, management.xlsx до написания нового бэка.

## 7. Не делать в рамках этого брифа

- Смена темы, шрифтов, «новый дизайн», тёмная тема, другой layout shell.
- Подмена реальных вероятностей демо-числами.
- Обещание supervised «пожар/проникновение» без меток — только честные proxy/индексы как сейчас в README.
- LDAP/AD — отдельный ops/security трек (в ТЗ есть, не блокер отображения на стенде с JWT).
- Полный цифровой двойник GIS — только дерево/карта на реальных тегах и GeoJSON заказчика.

## 9. Метрики успеха на защите

- Жюри входит с первого раза; нет красного «outdated» как главной эмоции в demo.  
- В очереди видны **разные** сценарии ТЗ, не только питание.  
- По инциденту за 10 секунд понятны: тип, место, вероятность, почему, что делать.  
- Network/Dashboard опираются на **один** контур объектов (tree/tags), а не «демо слева / ID справа».  
- Есть экран/блок с цифрами эффекта и выгрузкой XLSX.  
- Внешне сервис узнаваем как текущий Vena (Mineral Light), но читается как живая APM-панель, а не таблица сырых скоров.
