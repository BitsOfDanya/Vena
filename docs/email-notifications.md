# Почтовые уведомления

Почта — второй канал после уведомлений в интерфейсе. Письма отправляет backend по SMTP через очередь
в PostgreSQL: отправка переживает перезапуск, повторяется при ошибке и не задерживает запросы API.

## Настройка SMTP

Переменные backend (на стенде — `/opt/vena/shared/.env`, без Docker — `backend/.env`): `SMTP_HOST` и `SMTP_FROM`
(обязательны), `SMTP_PORT` (587), `SMTP_USER` или `SMTP_USERNAME` и `SMTP_PASSWORD` (без логина — без авторизации),
`SMTP_TLS=true` (STARTTLS с проверкой сертификата, по умолчанию), `SMTP_SECURE=true` (TLS сразу, порт 465).
Имена принимаются и с префиксом `VENA_` (логин — `VENA_SMTP_USERNAME`). Проверка — **Настройки → Уведомления →
Проверочное письмо** или `POST /api/v1/notifications/test` (роль `admin`), статус — `GET /api/v1/integrations/email/status`.

## Получатели и правила

Получатели — группы «Диспетчеры», «Эксплуатация» и «Руководство». Для каждого правила администратор выбирает группы
и каналы («в интерфейсе», «по почте»); настройки хранятся в PostgreSQL (`PUT /api/v1/settings/notifications`).

| Правило | Когда срабатывает | Уровень | Пауза повторов |
|---|---|---|---|
| Новые события | принят пакет потока СМВУ или загружен журнал | info | нет |
| Тревожное событие | в пакете есть тревожные события (вместо «Новых событий») | attention | 15 мин |
| Критический прогноз | инцидент уровня `critical` в новом снимке прогнозов | critical | 4 ч |
| Прогноз на 24 ч | инцидент уровня `attention` | attention | 6 ч |
| Новая связка | через API создано уведомление о связке событий (`type=pattern`) | attention | 2 ч |
| Работа назначена | назначен исполнитель; по умолчанию только в интерфейсе | info | нет |
| Работа просрочена | прошёл срок открытой работы; по умолчанию выключено | attention | 24 ч |
| Источник недоступен | поток СМВУ молчит дольше `VENA_SMVU_STALE_SECONDS` (900 с) или снимок старше `VENA_PREDICTION_STALE_SECONDS` | critical | 1 ч |

Письма о прогнозах уходят только для снимка по реальному журналу, не более
`VENA_PREDICTION_CRITICAL_LIMIT` (20) уведомлений на сценарий за пересчёт.

**Эскалация.** Критичное уведомление, не подтверждённое за 30 мин, эскалируется один раз: письмо группе
«Руководство» и уведомление «Эскалация: …» в интерфейсе. Проверка идёт раз в минуту, повтор исключает
отметка `notifications.escalated_at`; параметры — блок `escalation` (`enabled`, `minutes` 1–1440, `recipients`).
**Утренняя сводка** уходит в 08:00 по `VENA_TIMEZONE` группам «Руководство» и «Диспетчеры»; время меняется
без перезапуска, `VENA_DIGEST_ENABLED=false` отключает сводку.

## Формат письма

Тема — `VENA · <заголовок>`, тело — `multipart/alternative`: текст и HTML (таблицы с инлайн-стилями, до 600 px,
без картинок и внешних ресурсов, значения экранируются). Письмо о прогнозе содержит уровень, вероятность,
горизонт, объект, канал, сценарий, причину, первый шаг, последствия без реакции и кнопку «Открыть в VENA»
(`VENA_PUBLIC_URL` + `/pulse?notification=<id>` или `/actions?action=<id>`).

## Очередь доставки

Уведомление и письма (`delivery_log`) сохраняются в одной транзакции. Каждые 10 с фоновое задание берёт
ожидающие письма (`SELECT … FOR UPDATE SKIP LOCKED`) и отправляет их. После ошибки повтор через 1, 2, 4, 8
и 16 мин, после шестой неудачи — статус `failed`; сохраняется только класс ошибки. `sent` означает, что письмо
принял SMTP-сервер; без настроенного SMTP письма ждут в статусе `pending`. Журнал доставки (последние 50 писем,
счётчики по статусам) — `GET /api/v1/integrations/email/deliveries` (роль `admin`) и экран настроек.
Каналы webhook, Telegram и Teams не реализованы. Тесты — `backend/tests/test_email_delivery.py`,
`backend/tests/test_notification_rules.py`.
