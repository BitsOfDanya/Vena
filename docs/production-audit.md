# Проверка боевого стенда

Дата проверки: 29 сентября 2026. Адрес: https://5bit.online.

## Выполнено и проверено

| Задача | Результат и границы проверки |
|---|---|
| Контейнеризация, HTTPS, домен | Caddy, frontend, backend, PostgreSQL и ML worker работают в Docker; проверены публичные страницы и API. |
| Автодеплой | Push в `main` запускает GitHub Actions: сборка конкретного SHA, резервная копия, запуск контейнеров, проверка JWT/RBAC/API и публичного адреса. Ревизия сервера хранится в `/opt/vena/deployed-revision`. |
| JWT и пользователи | Проверен вход всех 20 учётных записей. `user1` — администратор; `user2`–`user20` — диспетчеры, роли остальных не менялись. Есть создание, блокировка, смена роли и сброс пароля с отзывом сессий. |
| CSV/XLSX через интерфейс | Раздел «Настройки → Интеграции», кнопка загрузки на главной странице. Предварительная проверка, ошибки строк, явное применение и отчёт с количеством принятых строк. Проверены CSV-журнал и XLSX-справочник с `ид_объект`. |
| Реестр оборудования | Обновление через файл, API и периодический опрос внешнего API; дерево объектов обновляется без пересборки. Реальное внешнее API заказчика ещё не подключено. |
| Поток событий | События и очередь доставки записываются одной транзакцией. Повторы не дублируются, конфликт идентификаторов отклоняется. Проверен повтор доставки после ошибки хранилища. Лента показывает записи базы с фактической датой, временем МСК и объектом. |
| Пересчёт прогнозов | Изолированный `infra/scripts/verify-stream.py` проверяет справочник → журнал → прогнозы → новые события → обновлённый снимок. Это техническая проверка на тестовых данных, не проверка журнала заказчика. |
| LDAP/AD | Реализованы настройки, поиск пользователя, проверка пароля, группы/роли, LDAPS и StartTLS с проверкой сертификата. Изолированно проверены успешный вход, неверный пароль и отказ недоверенному сертификату. Каталог заказчика пока не подключён. |
| Резервные копии | Включён `vena-backup.timer`; сохраняются PostgreSQL, каталог данных и очередь ML. Восстановление SQL проверяется в отдельной временной базе скриптом `infra/scripts/verify-backup.sh`; рабочая база не перезаписывается. |
| Удаление демонстрационных данных | После резервного копирования удалены старые демонстрационные работы, уведомления и точки прогнозов. В боевом режиме отключены автоматическое создание демонстрационной карты и вымышленная лента Pulse. |
| Русский интерфейс | Переведены роли и действия аудита, сообщения загрузок, управления пользователями и пустые состояния. Исходные значения в журнале заказчика сохраняются без изменения. |

Проверки кода: 83 backend-теста, Ruff, Mypy; 64 frontend-теста, TypeScript, production-сборка и ESLint изменённых компонентов. Через публичный API проверены 20 параллельных клиентов: 120 запросов без ошибок, максимальное время набора из шести запросов — 0,78 с. Проверены 15 страниц. Замер проведён на пустом реестре и **не подтверждает производительность на полном журнале**.

## Что мешает завершить приёмку на реальных данных

1. **Нет исходного журнала и справочника.** В проекте и `/opt/vena/shared/dataset` файлы не найдены. Таблицы `ml/results/tables` содержат результаты анализа и сведения об архиве, но не исходные события. На момент проверки реестр, журнал и прогнозы на стенде пусты; ML worker ожидает данные. Загрузка журнала заказчика не выполнена.
2. **Нет параметров каталога заказчика:** адрес LDAP/AD, доверенный CA, Base DN, служебная учётная запись, фильтры и группы ролей. Поэтому `ldap_available: false` пока является корректным статусом.
3. **Нет адреса и доступа к учётной системе заказчика.** Файловое и входящее API-обновление доступны; для автоматического внешнего опроса нужны URL и параметры авторизации.
4. **Нет реальных координат объектов.** Демонстрационная карта не является географией заказчика. Дерево строится по загруженному справочнику; для карты нужен GeoJSON/WKT с реальными координатами.

Инструкции и форматы: [интеграции](data-integrations.md), [аутентификация](authentication.md), [установка](installation.md).

После получения файлов следует сначала применить справочник, затем журнал, дождаться нулевой очереди публикаций и готового ML-снимка; сопоставить идентификаторы прогнозов с реестром и журналом. Затем передать новый пакет событий, проверить ленту и изменение снимка, выполнить повторный нагрузочный замер и резервное копирование. До этого стенд нельзя считать прошедшим приёмку на реальных данных.
