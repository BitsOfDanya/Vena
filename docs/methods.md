# Методы обработки данных и модели

Подробности — [ml/README.md](../ml/README.md).

## Данные

| Источник | Объём |
|---|---|
| Журнал событий СМВУ `ext-journal-2019…2026.csv` | ≈313,5 млн событий, 2019-01-01 — 2026-06-30, 19 типов датчиков |
| Справочник каналов | канал → тип инженерной системы, тип датчика, тег в дереве объектов |

Связь таблиц — `ид_канала_данных`. Журналы читаются потоково через DuckDB, события нужного типа датчика кэшируются в Parquet. События одного канала с одинаковым временем упорядочиваются по идентификатору записи, поэтому повторное извлечение даёт побайтно одинаковый результат.

## Постановка

Для канала в момент `t` оценивается риск начала целевого эпизода в интервале `(t, t+h]`.

| Модель | Датчик | Целевое состояние | Горизонт | Сценарий инцидента |
|---|---|---|---|---|
| `pump_24h`, `pump_72h` | состояние насоса | «Неисправен» | 24 / 72 ч | подтопление |
| `fan_24h`, `fan_72h` | состояние вентилятора | «Неисправен» | 24 / 72 ч | отказ вентиляции |
| `smoke_24h` | датчик дыма | «Неисправен» | 24 ч | пожар |
| `smoke_alarm_24h` | датчик дыма | «Обнаружен дым» | 24 ч | пожар |
| `phase_24h` | состояние фазы | «Обесточен» | 24 ч | потеря питания |
| `flood_24h` | состояние насоса | «Затоплен» (камера) | 24 ч | подтопление |
| `alarm_30m` | дым, газ, температура | подтверждение тревоги за 30 мин | 30 мин | ложные срабатывания |

Эпизод — события канала с целевым значением, разделённые паузами не более 6 ч; начало эпизода — первое событие.

## Конвейер

```
события → эпизоды → кандидаты → причинные признаки → модель → оценка риска → уровень → инцидент
```

1. **Кандидаты** — моменты, в которые оценивается риск: смена состояния, всплеск событий, восстановление, тревога, состояние рядом с отказом, а также контрольные точки при долгой тишине канала. Сами события отказа кандидатами не становятся.
2. **Признаки** (51) строятся только по событиям не позже `t`: частоты событий и тревог в окнах 10 мин — 30 сут, изменение темпа и всплески, межсобытийные интервалы, энтропия состояний, история эпизодов (число за 1–90 сут, интервалы между отказами, время с последнего отказа), сглаженные априорные частоты канала, календарные признаки. Регрессионные тесты проверяют, что будущие эпизоды не влияют на признаки текущего момента.
3. **Модели** — логистическая регрессия, CatBoost, LightGBM и их смесь; выбор по временной валидации.
4. **Скоринг** — каждый канал оценивается в момент своего последнего события, так распределение признаков совпадает с обучением.

## Валидация

Только временное разбиение, без случайного перемешивания, в два шага.

| Период | Роль |
|---|---|
| 2019–2023 (питание и тревоги — 2019–2024) | обучение эталонной модели |
| 2024 (питание и тревоги — 2025) | выбор эталонной модели, порогов, калибровка |
| до 2025 → 2025 | выбор рецепта переобучения: 4 алгоритма × 2 окна |
| 2019–2025 или 2023–2025 | обучение переобученной модели; калибровка по 2025 её версией, обученной до 2025 |
| 2026H1 | итоговая проверка всех моделей и решение, заменять ли эталон |

Перед границей обучения исключается 168 ч, чтобы метки не заглядывали в следующий период. Пороги выбираются до проверочного периода и переносятся на него без пересчёта. Кандидаты последних часов выгрузки без полного будущего окна в оценку не входят.

Метрики: AP (PR-AUC), ROC AUC, recall при precision ≥ 0,70, precision при recall ≥ 0,50; операционные — точность тревог после дедупликации, доля охваченных эпизодов, упреждение, число тревог в сутки.

## Вероятности

Все модели откалиброваны изотонической регрессией, поэтому API отдаёт вероятность начала события в горизонте (`score_type = calibrated_probability`). Калибратор обучается на периоде, которого модель не видела: 2025 для переобученных моделей (версией той же модели, обученной до 2025), 2024–2025 для моделей, обученных до 2024.

| Модель | ECE на 2026H1 | Доля событий |
|---|---|---|
| `pump_24h` | 0,031 | 0,117 |
| `pump_72h` | 0,038 | 0,259 |
| `fan_24h` | 0,004 | 0,042 |
| `fan_72h` | 0,010 | 0,092 |
| `smoke_24h` | 0,007 | 0,009 |
| `smoke_alarm_24h` | 0,008 | 0,018 |
| `phase_24h` | 0,022 | 0,253 |
| `flood_24h` | 0,037 | 0,086 |
| `alarm_30m` | 0,035 | 0,877 |

ECE — средний разрыв между предсказанной вероятностью и наблюдаемой частотой. Подробности — `ml/results/refit_study.json`, `ml/results/calibration.json`.

## Уровни риска

Уровень считается по некалиброванной оценке: изотонические ступени могут уравнять соседние значения.

| Модели | Границы critical / high / medium |
|---|---|
| насос, вентилятор, дым | верхние 0,1 % / 0,5 % / 2 % распределения оценок на тесте |
| питание | пороги, дающие precision 0,90 / 0,70 / 0,50 на валидации |
| подтопление | пороги, дающие precision 0,70 / 0,50 / 0,30 на валидации |

Переобученная модель получает границы, при которых на 2026H1 выдаётся столько же тревог каждого уровня, сколько выдавала заменённая.

Для питания доля положительных примеров около 29 %, поэтому квантильные границы оказались бы выше любой рабочей точки.

## Инциденты

Прогнозы уровней critical и attention с одинаковым сценарием группируются по локации — объекту и двум уровням секции из тега СМВУ (`16-2.1.1.4.22.` → `16-2.1.1`). Одна авария подстанции даёт один инцидент вместо десятков сигналов. Уведомление и черновик работы создаются на инцидент; повтор в пределах cooldown подавляется.

Для потери питания у инцидента есть собственная вероятность: хотя бы один канал локации обесточится за 24 ч. Она калибруется по ежедневным срезам 2025 года: 102 394 локация-дня, AP 0,530 при доле событий 0,297, ECE 0,003.

## Причины прогноза

Каждый прогноз сопровождается до трёх признаков с наибольшим положительным вкладом в оценку: SHAP-значения для CatBoost и LightGBM, коэффициент на стандартизованное значение для логистической регрессии. Причина с наибольшим вкладом становится основной причиной ситуации на Pulse и в уведомлении.

## Индекс здоровья

Для каждой локации — число 0–100: вероятность того, что за 24 ч на ней не начнётся ни одно событие по моделям. Индекс калиброван по суточным срезам 2025 года: при индексе 90–100 событие произошло в 3,8 % локация-дней, 75–90 — в 17 %, 50–75 — в 42 %, 25–50 — в 59 %, ниже 25 — в 79 %; ROC AUC 0,83.

## Рабочие правила

Насосы: пять каналов с наибольшим риском `pump_72h` в сутки — 76 % из них начинают отказ в течение 72 ч (2026H1), упреждение около двух суток. Вентиляторы: на уровне high `fan_72h` точность тревог 91 %, упреждение 45 ч. Питание: на уровне high 88 % тревог подтверждаются, охвачено 77 % отключений, упреждение 5 ч.

## Обратная связь

Решение диспетчера сохраняется с причиной из справочника и превращается в исход: подтверждён, норма, мониторинг, ложное срабатывание. Журнал прогнозов выгружает размеченные пары «прогноз → исход» для дообучения.

## Качество

Все production-модели на 2026H1 — периоде, который не использовался ни для обучения, ни для подбора параметров.

| Модель | Алгоритм, обучение | Доля событий | AP | ROC AUC | Recall при P ≥ 0,70 | Precision при R ≥ 0,50 |
|---|---|---|---|---|---|---|
| `pump_24h` | смесь LogReg + LightGBM, 2019–2025 | 0,117 | 0,329 | 0,689 | 0,061 | 0,261 |
| `pump_72h` | смесь LogReg + LightGBM, 2021–2023 | 0,259 | 0,508 | 0,659 | 0,277 | 0,418 |
| `fan_24h` | CatBoost, 2019–2025 | 0,042 | 0,240 | 0,879 | 0,034 | 0,196 |
| `fan_72h` | CatBoost, 2019–2025 | 0,092 | 0,540 | 0,922 | 0,192 | 0,538 |
| `smoke_24h` | CatBoost, 2019–2025 | 0,009 | 0,271 | 0,930 | 0,137 | 0,190 |
| `smoke_alarm_24h` | CatBoost, 2023–2025 | 0,018 | 0,218 | 0,858 | 0,044 | 0,114 |
| `phase_24h` | CatBoost, 2023–2025 | 0,253 | 0,751 | 0,874 | 0,584 | 0,765 |
| `flood_24h` | LightGBM, 2019–2025 | 0,086 | 0,254 | 0,701 | 0,023 | 0,152 |

Переобучение на данных по 2025 году заменило эталон у насоса 24 ч (AP 0,292 → 0,329), дыма (0,209 → 0,271), подтопления (0,234 → 0,254) и питания (0,674 → 0,751; у эталона, обученного по 2024, на 2026H1 вероятности завышены, ECE 0,085 → 0,022). Смесь насоса 72 ч и вентиляторы остались прежними: переобучение не улучшило их на 2026H1.

Формальная цель precision > 0,70 при recall > 0,50 достигнута для питания: при precision 0,70 recall 0,58. Для насосов и вентиляторов не достигнута: больше половины эпизодов «Неисправен» — одиночные события нулевой длительности, и порогом цель не достигается даже при подборе по самим тестовым меткам. Все проверенные подходы — таблица в [ml/README.md](../ml/README.md#все-проверенные-модели-и-подходы).

## Срабатывание дымового датчика

`smoke_alarm_24h` оценивает вероятность того, что датчик дыма перейдёт в «Обнаружен дым» в ближайшие 24 ч. На 2026H1 AP 0,218 при доле событий 0,018 (сглаженная частота срабатываний канала даёт 0,022), ROC AUC 0,86. Это состояние датчика, а не подтверждённый пожар; подтвердится ли тревога, оценивает `alarm_30m`.

## Подтопление и погода

Модель `flood_24h` прогнозирует затопление камеры насосной станции за 24 ч. Сравнивались четыре набора признаков на одном разбиении:

| Признаки | AP валидация 2024 | AP тест 2025 — 2026H1 |
|---|---|---|
| события | 0,252 | 0,220 |
| + частота включения насосов | **0,252** | **0,235** |
| + прошлая погода | 0,234 | 0,230 |
| + прогноз осадков на сутки | 0,238 | 0,217 |

Выбран набор «события + частота включения насосов»; production-модель переобучена на 2019–2025 (AP 0,254 на 2026H1). Погода не улучшает прогноз. Корреляция ежедневного числа затоплений с осадками по Москве — 0,03, в дни сильных дождей затоплений 5,2 в сутки против 5,0 в остальные. Затопления камер в журнале связаны с работой насосов, а не с ливнями, поэтому метеоданные в модель не входят (`ml/results/flood_variants.json`, `ml/results/seasonality.json`).

## Ложные срабатывания

Тревога дыма, газа или температуры считается подтверждённой, если в течение 30 минут повторяется на канале, срабатывает соседний канал той же группы тегов или датчик остаётся в состоянии тревоги. Отметки оператора об истинности тревог в данных нет, поэтому неподтверждённая тревога — кандидат в ложную, а не доказанно ложная.

Модель `alarm_30m` (LightGBM, обучение 2019–2024, валидация 2025) на отложенном 2026H1: ROC AUC 0,85, PR-AUC 0,97. Порог сохраняет 90 % подтверждающихся тревог и помечает 16 % тревог для проверки перед выездом. Среди помеченных 45 % не подтвердились при доле неподтверждённых 12 % — в 3,7 раза чаще; отсеивается 60 % неподтверждающихся тревог.

## Несанкционированный доступ

Разметки проникновений в данных нет, поэтому это индекс для проверки диспетчером, а не вероятность. Рассматриваются срабатывания точек входа — дверей, люков, датчиков разбития стекла — в то время, когда объект стоит на охране (5,5 % всех срабатываний, 45 в сутки). Индекс 0–1 складывается из редкости срабатывания в этот час недели для данного датчика (0,4; считается только по прошлым срабатываниям), типа точки входа — люк или стекло (0,25), ночного времени (0,2) и цепочки срабатываний на объекте за 10 минут (0,15).

Порог выбран так, чтобы на проверку выходило около 5 событий в сутки из 45. Среди отмеченных ночных событий 14 % против 2,8 % по всем срабатываниям на охране, люков и стёкол — 6,4 % против 1,0 %, цепочек — 74 % против 21 %. Снятие с охраны вход не подтверждает: после открытия двери на охраняемом объекте его снимают с охраны в течение 15 минут лишь в 3 % случаев, поэтому этот признак не используется (`ml/results/access_analysis.json`).

## Сезонность и прогноз нагрузки

`ml/results/seasonality.json` содержит помесячную частоту начала эпизодов на 100 каналов и долю по сезонам для затоплений, отказов насосов, вентиляторов, датчиков дыма, обнаружения дыма и потери питания.

Число новых эпизодов каждого типа в сети прогнозируется на 1–14 дней (`ml/run_workload_forecast.py`, API `GET /api/v1/analytics/event-types`): градиентный бустинг с пуассоновской потерей на дне недели, сезоне, праздниках, среднем за 7–91 день и тех же днях год назад, вариант с погодой; метод выбирается на 2025 вместе со средним за 28 дней. Ошибка суммы за неделю на 2026H1: потеря питания 13 % (среднее за 28 дней — 14 %), затопление камер 38 % (47 %), неисправность дымовых датчиков 77 % (91 %); у отказов насосов модель уступила среднему (37 % против 30 %), у вентиляторов выбрано среднее (32 %).

## Дообучение

`ml/run_production_refresh.py` заново извлекает события и в два шага пересобирает модели: эталонные рецепты на своём разбиении (замена, только если метрика не хуже текущей более чем на 0,005), затем переобучение на последнем полном годе с заменой, если претендент лучше на последнем полугодии. После этого пересчитываются отчёты, индекс здоровья, прогноз нагрузки, реестр моделей и снимок.

## Производительность

Пакетный прогноз по 263 612 кандидатам насосов (2026H1) из исходных CSV занимает около 27 с на 14-ядерной машине: чтение журнала 9,7 с, кандидаты 2,5 с, признаки 14,4 с, инференс 0,4 с. Это укладывается в требование ≤ 300 с на прогноз (ТЗ, раздел 9) для пакетного режима.

## Ограничения

- Прогнозируется состояние канала в журнале, а не подтверждённый физический отказ; меток реальных пожаров и проникновений в данных нет. Подтопление представлено состоянием камеры «Затоплен».
- Нет подтверждения тревог оператором, возраста оборудования, истории ремонтов, геопривязки и данных СКУД; ложность тревоги и подозрительность доступа оцениваются косвенно.
- Решение о замене модели и итоговые метрики считаются на одном периоде 2026H1, поэтому оценка лучшей из двух-трёх моделей немного оптимистична; независимая проверка — прогнозы после конца журнала (`/api/v1/ml/prospective`).
- На каналах с короткой историей смесь моделей насоса уступает одиночной модели; для каналов с историей меньше 30 сут используется одиночная.
- Метод требует большого числа размеченных эпизодов: на открытом наборе MetroPT-3 с четырьмя отказами он неприменим (ROC AUC 0,37).
