# Vena

Веб-приложение для наблюдения за инженерной инфраструктурой и работы с прогнозами инцидентов. Исходное техническое задание: `docs/descriptions/8. ДЖКХ.pdf`.

## Запуск

Требуются Docker и Docker Compose.

```bash
docker compose up -d --build
```

| Компонент | Адрес |
|---|---|
| Интерфейс | http://localhost:3100 |
| API и Swagger | http://localhost:8100/docs |
| PostgreSQL | localhost:5433 |

Порт 5433 выбран для локального PostgreSQL, поскольку 5432 может быть занят. Данные БД и исходные файлы импорта лежат в Docker volumes `vena-postgres` и `vena-uploads`. Схема обновляется миграциями Alembic при старте API. Контейнер `import-worker` обрабатывает загруженные файлы отдельно от HTTP-запросов.

Роль выбирается в форме регистрации; по умолчанию аккаунт обеих ролей создаётся без кода. Если задан `VENA_DISPATCHER_INVITE_CODE`, он потребуется для создания диспетчера после первого аккаунта. Аккаунты используют JWT в HttpOnly cookie, а разрешения проверяет API. Для эксплуатации задайте собственные `VENA_JWT_SECRET`, `VENA_POSTGRES_PASSWORD` и `VENA_DISPATCHER_INVITE_CODE` в окружении Compose. При публикации через HTTPS также задайте `VENA_AUTH_COOKIE_SECURE=true`, актуальный `VENA_CORS_ORIGINS` и `VENA_PUBLIC_URL`.

## Работа с данными

Оператор загружает CSV/XLSX до 25 МБ в разделе «Загрузки». Поддерживаются три набора:

| Набор | Обязательные поля | Примеры заголовков из ТЗ |
|---|---|---|
| Журнал датчиков | ID записи, ID канала, значение, дата | `ИД записи журнала`, `ИД канала данных`, `Текущее значение`, `Дата записи` |
| Реестр каналов | ID канала, тег объекта | `ИД канала данных`, `Тег в дереве объектов` |
| Дерево объектов | ID объекта, название | `ИД объекта`, `Название` |
| Связи сети | ID исходного и целевого объекта | `source_id`, `target_id` |

Также принимаются английские имена полей `source_record_id`, `channel_id`, `value`, `occurred_at`, `object_tag`, `object_id`, `name`. Для отображения объекта на карте добавьте `latitude`/`longitude` либо `широта`/`долгота`; можно указать `district`, `object_type`, `status`. Связи загружаются после объектов. Необязательные поля включают `channel_type`, `display_name`, `system_name`. Даты без часового пояса трактуются как время Москвы; CSV читается в UTF-8 или CP1251 с разделителем `,`, `;` или табуляцией. Повторный файл определяется по SHA-256; повторные записи журнала — по паре ID записи и ID канала. Статус, число принятых/отклонённых строк и первые ошибки доступны в истории импортов. Исходные файлы должны быть обезличены **до загрузки**, согласно ТЗ.

### Демонстрационная карта Москвы

После запуска Compose выполните один раз:

```bash
docker compose exec backend python -m app.db.seed_geo
```

Команда идемпотентно создаёт в PostgreSQL 117 вымышленных геообъектов, 153 связи, 108 каналов и 1512 событий за 14 дней. Карта доступна на `http://localhost:3100/map` обеим ролям. Подложка использует MapLibre и публичный тёмный стиль OpenFreeMap; для неё нужен доступ браузера в интернет. Координаты и линии сидера не обозначают реальные коммуникации Москвы. Если есть реальные геоданные, оператор может загрузить объекты и связи CSV/XLSX вместо демонстрационного набора.

Разделы «Обзор», «Данные» и «Карта» показывают записи из PostgreSQL. Оператору доступны эти разделы и загрузки. Диспетчер также видит существующие разделы прогнозов, уведомлений и работ; решения и изменения работ доступны только ему. Журнал API `GET /api/v1/audit` доступен диспетчеру и фиксирует метод, путь, код ответа и ID инициатора для изменяющих запросов.

## Прогнозный контур

Имеющийся в репозитории ML-модуль находится в `ml/`. Замороженные модели используют подготовленный исторический датасет и рассчитываются отдельно командой `cd ml && python score_snapshot.py`. API читает `ml/results/predictions/snapshot.json` и хранит историю прогноза, уведомления, действия диспетчера и результат. Если снимка нет, интерфейс показывает его недоступность; значения не подменяются демонстрационными. Сырые загрузки в PostgreSQL пока **не подключены к признакам этих моделей**. Их прогнозы нельзя считать прогнозом по только что загруженному файлу.

Оценки моделей являются `risk_score`, пока калибровка вероятностей не подтверждена. Метрики, направления и ограничения описаны в [ml/README.md](ml/README.md). Существующие экраны «Пульс», «Сеть» и «История» используют детерминированный демонстрационный набор; это явно обозначено в интерфейсе.

Для полноценной эксплуатации по ТЗ ещё нужны данные и контракт интеграции от Заказчика: исторические метки пожаров, подтоплений, проникновений и отказов; геоданные GeoJSON/WKT; данные СМВУ, ОДС, заявок и плановых работ. Без них нельзя честно валидировать вероятности и 24-часовые прогнозы этих событий, построить карту реальных объектов и проверить метрики на фактических инцидентах. LDAP/AD, TLS-терминация, резервное копирование и нагрузочное подтверждение 20 пользователей также относятся к развёртыванию в инфраструктуре Заказчика. В текущем Compose предусмотрен локальный контур разработки.

## Структура

```text
backend/    FastAPI, SQLAlchemy/Alembic, PostgreSQL, обработчик импорта
frontend/   Next.js App Router, TypeScript, FSD, TanStack Query, shadcn/Radix
ml/         Признаки, артефакты моделей, офлайн-скоринг и эксперименты
docs/       Техническое задание
```

API: `GET /api/v1/health`, `/auth/{register,login,logout,me}`, `/imports`, `/data/{summary,activity,events,channels,objects}`, `/map/network`, `/audit`, а также существующие `/predictions`, `/notifications`, `/actions`, `/settings`, `/ml`. Полный контракт доступен в Swagger.

## Локальная разработка и проверки

```bash
cd backend && uv sync && uv run alembic upgrade head && uv run fastapi dev
cd frontend && pnpm install && pnpm dev
```

Фронтенду нужны `NEXT_PUBLIC_API_URL=http://localhost:8000` и `NEXT_PUBLIC_VENA_WORKFLOW_MODE=api`; образ Compose использует порт API 8100. Примеры переменных есть в `backend/.env.example` и `frontend/.env.example`.

```bash
cd backend && uv run ruff check . && uv run mypy app && uv run pytest
cd frontend && pnpm lint && pnpm typecheck && pnpm test && pnpm build
cd ml && python -m pytest
```
