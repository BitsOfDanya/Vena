# VENA

Сервис прогнозирования инцидентов и управления ремонтными работами инженерных коллекторов Москвы (кейс №8, АО «Москоллектор», ЛЦТ 2026).

По журналу событий СМВУ модели оценивают вероятность отказа насосов, вентиляторов, датчиков дыма, срабатывания дымовых датчиков, потери питания и затопления камер на горизонте 24–72 ч, отмечают тревоги с низкой вероятностью подтверждения, выделяют подозрительные срабатывания точек входа на охраняемых объектах и прогнозируют число инцидентов каждого типа на две недели вперёд. Прогнозы собираются в инциденты по локации и сценарию: подтопление, пожар, потеря питания, отказ вентиляции. Диспетчер получает уведомление и черновик работы, фиксирует решение с причиной из справочника, а результат возвращается в журнал для дообучения.

## Стенд

Сервис развёрнут: **http://5.129.225.86** (интерфейс), http://5.129.225.86/api/v1/health (API).

Стек: Caddy → Next.js / FastAPI → PostgreSQL 16 и отдельный ML-контейнер, который раз в час пересчитывает снимок прогнозов замороженными моделями. Каждый push в `main` через GitHub Actions собирает образы, делает резервную копию базы, применяет миграции, проверяет сервис smoke-тестами и при сбое возвращает предыдущий релиз. Ежедневные резервные копии — systemd-таймер. Настройка сервера, HTTPS и откат — [infra/README.md](infra/README.md).

По умолчанию ML на стенде работает в режиме `demo`: настоящие модели оценивают синтетические каналы, журнал СМВУ на сервер не загружается. Режим `journal` включается загрузкой журнала в `/opt/vena/shared/dataset` и `VENA_ML_MODE=journal`.

## Модели

Качество на первом полугодии 2026 года, которое не использовалось ни для обучения, ни для подбора параметров. Подробности, протокол и все проверенные подходы — [ml/README.md](ml/README.md).

| Модель | Что прогнозирует | Алгоритм | Доля событий | AP | ROC AUC |
|---|---|---|---|---|---|
| `pump_24h`, `pump_72h` | отказ насоса за 24 / 72 ч | смесь LogReg + LightGBM | 0.117 / 0.259 | 0.329 / 0.508 | 0.689 / 0.659 |
| `fan_24h`, `fan_72h` | отказ вентилятора за 24 / 72 ч | CatBoost | 0.042 / 0.092 | 0.240 / 0.540 | 0.879 / 0.922 |
| `smoke_24h` | неисправность дымового датчика за 24 ч | CatBoost | 0.009 | 0.271 | 0.930 |
| `smoke_alarm_24h` | срабатывание дымового датчика за 24 ч | CatBoost | 0.018 | 0.218 | 0.858 |
| `phase_24h` | потеря питания за 24 ч | CatBoost | 0.253 | 0.751 | 0.874 |
| `flood_24h` | затопление камеры насосной за 24 ч | LightGBM | 0.086 | 0.254 | 0.701 |
| `alarm_30m` | подтверждение тревоги за 30 мин | LightGBM | 0.877 | 0.972 | 0.848 |

AP сравнивается с долей событий: у случайного ранжирования AP равна ей. Вероятности откалиброваны (ECE 0.004–0.038). У потери питания при precision 0.70 recall 0.58. Для насосов рабочее правило — пять насосов с наибольшим риском `pump_72h` в сутки: 76 % из них начинают отказ в течение 72 ч. Прогноз числа инцидентов на неделю: потеря питания — ошибка 13 %, затопление камер — 38 %.

## Локальный запуск

```bash
docker compose up -d --build
```

- Интерфейс: http://localhost:3100
- API: http://localhost:8100/docs

Вход — по API-ключу из `VENA_API_KEYS_JSON` (локальные значения по умолчанию — в `compose.yaml`). Прогнозы читаются из `ml/results/predictions/snapshot.json`; как его построить — в [docs/installation.md](docs/installation.md#снимок-прогнозов).

## Структура

```
backend/    FastAPI, PostgreSQL: прогнозы, инциденты, уведомления, работы, журнал, RBAC, аудит
frontend/   Next.js: интерфейс диспетчера (Feature-Sliced Design)
ml/         конвейер данных, обучение, замороженные модели, снимок прогнозов, эксперименты
infra/      production-развёртывание: Caddy, образы, деплой, резервные копии
docs/       документация
compose.yaml      локальный запуск
.github/workflows автодеплой на стенд
```
