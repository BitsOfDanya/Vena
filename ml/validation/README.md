# Три варианта проверки VENA

Запуск использует существующие артефакты `pump_24h`, `pump_72h`, `flood_24h`,
`phase_24h`, fallback насоса, их калибраторы и пороги high. Артефакты не меняются.
Это проверка ML offline, а не проверка API, интерфейса, доставки писем или SLA.

## Запуск

Из корня репозитория:

```bash
UV_CACHE_DIR=/private/tmp/vena-uv-cache uv venv ml/.venv --python 3.12
UV_CACHE_DIR=/private/tmp/vena-uv-cache uv pip install --python ml/.venv/bin/python -r ml/validation/requirements.txt
mkdir -p ml/external_datasets/metropt3
curl --fail --location --retry 2 'https://archive.ics.uci.edu/static/public/791/metropt%2B3%2Bdataset.zip' -o ml/external_datasets/metropt3/source.zip
MPLCONFIGDIR=/private/tmp/vena-matplotlib ml/.venv/bin/python ml/run_independent_validation.py
```

Отчёт: `ml/results/independent_validation/REPORT.md`. Протокол записывается перед
расчётом: версии пакетов, хеши кода, моделей/калибраторов, пороги, периоды, seed.
В конце проверяется неизменность артефактов. Для нового эксперимента передайте
новую папку `--output`, чтобы сохранить предыдущий результат.

Проверки оценщика:

```bash
cd ml
MPLCONFIGDIR=/private/tmp/vena-matplotlib .venv/bin/python -m pytest validation/test_validation.py pipeline/tests/test_feature_causality.py
```

## 1. Новые реальные данные

Без новой выгрузки результат имеет статус `blocked_missing_data`; метрики старого
2026H1 не подставляются. Подключение:

```bash
ml/.venv/bin/python ml/run_independent_validation.py --real-manifest /absolute/path/manifest.json --output ml/results/validation_with_real_data
```

Скопируйте `real_manifest.example.json` рядом с подготовленными CSV. Пути внутри
manifest разрешаются относительно него. `attested_unseen: true` означает явное
подтверждение владельца эксперимента, что период не использовался для обучения,
выбора моделей/порогов и разработки. Сам код не может проверить такую историю.
Не выставляйте это поле автоматически ради запуска.

- `events.csv`: `channel_id,ts,raw_value,alarm_flag` (alarm_flag 0/1). Один тип
  оборудования, соответствующий выбранной модели. Включите историю до начала
  теста, желательно 90 дней. Неизвестное прошлое не заполняется фиктивными данными.
- `confirmed_episodes.csv`: `channel_id,episode_start,episode_end`. Подтверждённые
  физические эпизоды целевого типа из ОДС/актов. Отсутствие строки означает
  отсутствие происшествия только при полном покрытии журнала.
- Все timestamps должны быть без timezone offset, в одной явно указанной
  исходной временной зоне. Время не переводится автоматически: календарные
  признаки production-моделей чувствительны к локальному часу.
- `coverage_end` — последний момент полного покрытия входов и разметки. Последние
  24/72 ч без будущего окна автоматически не оцениваются. Интервалы пропусков
  разметки следует исключить подготовкой отдельных запусков с полным покрытием.
- Manifest содержит источник/версию разметки и интервал после 30.06.2026.

Это независимость по периоду/разметке, не доказательство переноса на другого
оператора. Оценщик поддерживает один целевой model_id на real-manifest; для разных
типов оборудования запустите отдельные manifest и output.

## 2. Внешние данные

[MetroPT-3, UCI](https://archive.ics.uci.edu/dataset/791/metropt+3+dataset),
Davari, Veloso, Ribeiro & Gama (2021), DOI 10.24432/C5VW3R, CC BY 4.0.
CSV загружается из официального архива; в отчёте записывается SHA-256.

Один компрессор преобразуется в один событийный канал:
`DV_eletric` → работа под нагрузкой/разгрузка, `LPS` → низкое давление,
`Oil_level` → низкий уровень масла. Записываются только изменения объединённого
состояния. Приоритет: масло, давление, режим. Аналоговые величины не используются.
Отчёты о четырёх утечках доступны исключительно оценщику, не признакам.
Ни одного искусственного `Неисправен` по истинной метке не добавляется.

Применяются замороженные модели насосов на периоде 01.04–01.08.2020 (с обрезкой
по фактическому концу CSV). Никакого обучения на MetroPT или подбора порогов нет.
Старый `validate_external.py` обучал отдельную модель; его отчёт не перезаписывается.
MetroPT ранее изучался, поэтому новый результат — диагностический тест переноса,
не новый закрытый тест. Различия домена, разметки и адаптера ограничивают выводы.

## 3. Симуляция

Независимая от ML генерация: `dV = (приток − откачка) dt − перелив`, два насоса
с гистерезисом, камера с постоянной площадью. Шаг 5 минут, 90 дней, 30 дней истории.
По умолчанию 8 seed × 8 сценариев; одинаковые seed дают парные параметры объектов.

Сценарии: норма, деградация двух насосов, внезапный отказ одного, потеря питания,
повышенный приток, зависший уровнемер, ППР, пропуск телеметрии. Деградация задаёт
снижение производительности; физический отказ определяется эффективностью ≤25%.
Эти параметры — допущения симулятора, не оценённая физика реальной камеры.
Нормальные режимы не подгоняются к распределению обучения модели.

Физическая истина хранится отдельно от наблюдаемых состояний. ППР может выдавать
`Неисправен` при исправном агрегате. Потеря питания не размечается механическим
отказом. Подтопление оценивается по первому каналу станции, чтобы одно затопление
не удваивало число эпизодов. Насосы оцениваются по отдельным агрегатам.

## Метрики и причинность

Сетка прогнозов — каждые 6 ч, порог — сохранённый high по raw_score. Вероятность
калибруется production-калибратором с тем же ограничением 0.001–0.99, что в снимке.
История короче 30 дней включает штатный fallback там, где он предусмотрен.
Факт строго в `(t, t+h]`; активные физические эпизоды исключены из популяции оценки
начала нового эпизода. Последние неполные горизонты исключены. Истина не является
входом модели, включая историю прошлых физических неисправностей.

Для предупреждений — cooldown 24 ч на канал/модель. Recall считается по отдельным
эпизодам с полным предшествующим окном. Precision при отсутствии предупреждений
равен `null`, а не 100%. AP без положительных примеров также `null`.
AP, Brier и base rate относятся к точкам прогноза, операционные метрики — к
дедуплицированным предупреждениям. Baseline: число наблюдаемых целевых эпизодов за
7 дней; его правило `>0` не имеет одинакового бюджета тревог с моделью, поэтому
precision нельзя сравнивать без учёта числа предупреждений.

Пакетный расчёт воспроизводит признаки строго обрезанной истории. В отдельном
адаптере EWMA ограничивается последним наблюдённым событием на момент прогноза:
старый batch-helper продлевает ряды до будущего события и иначе обрабатывает дни
тишины. Production-код не меняется. Тесты сравнивают все признаки с вызовом
production-функции отдельно на каждом префиксе, включая длинные паузы.

Интервалы для симуляции — bootstrap по seed, сохраняющий парные сценарии и каналы.
Это неопределённость внутри искусственного мира. Для одного MetroPT-компрессора с
четырьмя отказами популяционные интервалы не выдаются.
